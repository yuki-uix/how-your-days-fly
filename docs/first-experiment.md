# 实验 001：设计一份真正愿意使用的年历

## 问题

AI 能否理解一个人的日历偏好，产出愿意实际使用的设计，并根据反馈做有针对性的修改？

本轮以 2027 年家用挂墙年历为真实任务。审美偏好尚未收集；不能把模型的默认风格当成用户偏好。当前记录见 `experiments/001-calendar/record.json`。

## 需要的输入

- 过去喜欢或认真考虑过的日历：公开链接、用户自己的描述，或保存在本地的参考图。
- 每个参考具体吸引人的部分，以及不喜欢或不需要的部分。
- 使用方式：查日期、感受时间经过、装饰、记录等，可并存或由用户补充。
- 必要约束：尺寸、语言、周起始日、信息内容；暂不确定的项目保持开放。

不要求用户先掌握设计术语。可以用方案对比澄清难以描述的偏好。若暂时没有参考，展示少量有实质区别的探索方向，并将其标为假设。

## 第一轮工作

1. 区分明确需求、参考中的偏好证据、模型推测和待确认项。
2. 提出少量原创方向，配上可比较的简易视觉样稿，说明各自怎样组织时间，以及视觉选择的依据；不只更换配色或列出风格名称。
3. 制作选定方向的可编辑版本，日期由代码提供，视觉实现独立保留。
4. 检查日期、文字、尺寸和输出；另行收集用户对设计的评价。
5. 根据具体反馈修改对应部分，记录哪些保留、哪些改变。
6. 保存配方并重新渲染；再尝试换年份，检查原有设计关系是否保持。

## 验收

| 维度 | 需要的证据 |
| --- | --- |
| 技术正确 | 日期与星期正确、无漏日、实际尺寸下可用、无意外裁切或文字碰撞 |
| 设计满意 | 用户明确愿意实际使用，并记录具体评价；不能由 agent 代签 |
| 修改有效 | 用户能辨认要求的改动，已认可部分得到保留 |
| 可复现 | 选定的源文件、字体/素材版本和参数能够重新产生设计 |
| 可扩展 | 换年份后仍正确；之后以偏好不同的用户和其他日历尺度继续验证 |

当前只提供日期数据工具。视觉实现、用户认可与配方重放均未完成。

## 下一步

本轮采用模式优先的探索方式：先按[模式分类](../.agents/skills/calendar-design-lab/references/patterns.md)的设计词汇制作 A–H 样本。A–E 固定年份与相近的中性视觉语言来比较结构，F/G/H 再比较月、周、日尺度和内容角色。源码与实验配方见 `studies/pattern-atlas/`；这不是已经认可的个人设计。

收集用户对结构、层次和内容角色的具体选择，再给选中的结构尝试不同视觉语言。未经用户认可前，不把任何探索方向上架为“已验证模板”。
