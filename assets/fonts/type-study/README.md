# 字体研究用源资产

核对日期：2026-10-30。这里保存两套**未经修改的原始可变 TrueType 文件**与各自完整 OFL；[manifest.json](manifest.json)记录官方来源、版本、Git blob、SHA-256、轴及实测。没有复制真实案例的文字、图像、反馈或改名字体工作副本。

## 收录与使用条件

| 家族 | 版本 | `wght` 范围／原始默认值 | 文件大小 | 用于本轮比较的角色 |
|---|---|---|---|---|
| Noto Serif SC | 2.003-H1 | 200–900／200 | 25,125,512 bytes | 比较宋体笔画、标题与附注的关系 |
| Noto Sans SC | 2.004-H2 | 100–900／100 | 17,772,300 bytes | 比较黑体、日期查读与较小文字 |

原始默认字重不是 400。调用时应明确设置所需字重；两份文件都**没有 `opsz` 轴**。用它们做视觉研究，不预设“宋体天然适合书籍”“黑体只能承担功能文字”。

字体依据 OFL 1.1 原样再分发，保留各目录的版权与完整许可，不能单独售卖字体，也不能将字体改以项目许可证发布。Noto Sans SC 的许可声明了保留名称 `Source`；修改、转换或子集化时重新检查 OFL 条件及名称。Noto Serif SC 这份许可未声明保留名称。以上是对随附文件的记录，完整条件以各自 OFL 为准。

## 实测结果与局限

在内存中将可变字体实例化为 `wght=400`，检查默认 `cmap` 对应字形的 `hmtx` advance，不应用 GSUB/GPOS。两套均覆盖通用试样 `年月周日 春夏秋冬 0123456789 Aa Il1，。！？（）《》`；这不是完整中文覆盖认证。

| 文件／字重 | 默认数字宽度，单位为 1/1000 em | 可以据此判断什么 |
|---|---|---|
| Noto Serif SC 400 | 0=557、1=471、2=558、3=557、4=555、5=558、6=558、7=549、8=558、9=562 | 默认数字不是等宽；尚未应用数字替代功能 |
| Noto Sans SC 400 | 0–9 均为 555 | 默认数字等宽；这并不证明所有数字样式相同 |
| 已有 Instrument Serif Regular | 249–460 | 比例宽数字；此具体文件缺少本次中文字符 |
| 已有 IBM Plex Mono Regular | 0–9 均为 600 | 全家族的中文宣传不能推及这个英文文件 |
| 已有 IBM Plex Sans Condensed Regular | 0–9 均为 540 | 此具体文件缺少本次中文字符 |

等宽／比例宽与等高／旧式是不同问题。仅凭 advance 无法判定数字高度类别；发现 `tnum` 等功能标签也不代表导出已经启用。详细字形墨迹框与标签见清单。

当前 `design_scene.py` 的逐码点取字与 advance 路径没有完整 GSUB/GPOS 塑形和功能选择。把字体放进资产库不会自动获得中西文排版、标点压缩、行禁则或全部字距调整能力。可变 TTF 能否被某条 PDF 路径正确使用，也需要输出验证。

这些约 43 MB 的文件作为**源资产**保留，不应直接当作网站首次访问的交付体积。网页字体子集、WOFF2、静态实例或转曲输出分别需要来源与衍生记录；生成字体工作副本时保留原始文件、许可和生成参数，渲染后检查缺字、字重及数字形式。这里没有发布任何修改后的实例。

## 为什么暂不加入第三套中文字体

本地已有的 LXGW WenKai Lite Regular 1.530 与[作者官方文件](https://github.com/lxgw/LxgwWenKai-Lite/tree/main/fonts/TTF)的 Git blob、尺寸一致，OFL 也与[官方许可](https://github.com/lxgw/LxgwWenKai-Lite/blob/main/OFL.txt)一致；它可作为后续表达性字形比较的候选。此次保留两套核心中文家族以控制源资产体积，未把它复制进公开目录。

实测 LXGW 的通用试样无缺字，默认数字均为 600/1000 em；仍不能据此断言所有书名、地区字形或 Unicode 变体序列都获支持。其许可有中文及 `LXGW` 等保留名称与附加许可，未来转换／改造应重新读取原许可，不能套用 Noto 的名称条件。

选择方法、反例及一手阅读范围见[字体研究](../../../docs/research/font-selection.md)。
