# Calendar review

Use this reference for visual review and feedback. Choose criteria relevant to the brief; the list is not a fixed aesthetic rubric.

## Technical evidence

- Confirm the intended period, locale, week start, date/weekday mapping, and any sourced calendar annotations.
- Inspect the actual output for missing glyphs, clipping, unintentional collisions, and whether text works at the intended viewing or print size.
- Inspect the exported file as well as the editor preview when export is part of the deliverable.
- Treat holiday schedules, lunar information, and solar terms as separate data requirements; the bundled Gregorian helper does not establish them.

## Design evidence

- Does the composition express the proposed relationship to time?
- Is the hierarchy useful for this person's use: annual overview, month relationships, weekly rhythm, or daily focus?
- Do visual decisions have evidence in the brief or selected direction, or are they unexplained defaults?
- Is the work coherent and distinctive in the ways the user cares about?
- What does the user want to keep, change, or explore next?

For a type/layout review, use the actual specimen and composition study in [typographic-composition.md](typographic-composition.md). Examine the entire page at thumbnail size and the real text at intended size: hierarchy, image/title/date relationships, optical alignment, punctuation, and unnecessary repeated information. A license check, glyph check, aligned grid or clear bounding box establishes none of those aesthetic choices by itself.

An agent may critique these questions, but only the user can confirm personal satisfaction. Record the actual response without upgrading it into broader preferences.

## Feedback record

For a useful revision, keep the feedback, interpretation, changed source/parameters, intentionally retained decisions, and resulting preview. Mark an interpretation as provisional until supported. If feedback could imply materially different changes, clarify with a comparison rather than silently choosing.

Use [design-exploration.md](design-exploration.md) for the keep/change/unknown loop and [case-record.md](case-record.md) for revision-scoped evidence. Retaining an accepted date arrangement does not approve the new image, layout or entire revision. A record check only checks the recorded structure and file identities.

Example: “time feels fragmented” could concern month grouping, visual interruptions, or how weeks cross month boundaries. Establish which feature caused the impression before changing all three.
